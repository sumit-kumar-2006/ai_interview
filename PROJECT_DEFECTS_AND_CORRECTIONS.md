## Complete Project Defect Register

The following matrix documents all verified technical, mathematical, coding, architectural, database, and documentation defects discovered during independent examination.

| **DEF-001** | **Database Engine Mismatch (MySQL vs. SQLite)** | `backend/app/database.py`<br>`backend/app/main.py`<br>`AI_Interview_Analyzer_ML_Project_Report.docx` (Ch. 1, 8) | **CRITICAL** | Documentation and UML ER diagrams claim the system uses **SQLite**, but `database.py` hardcodes a connection to **MySQL via PyMySQL** (`mysql+pymysql://root:@127.0.0.1:3306/ai_interview_analyzer`). | **DEF-002** | **Random Forest Regressor Disconnected from Primary Scoring** | `backend/app/evaluator.py`<br>(lines 26–38, 549–576)<br>`backend/app/main.py` | **CRITICAL** | The project documentation highlights the 350-tree Random Forest model as the core automated grading engine. An external examiner checking code will see the primary score is rule-based, not ML-predicted. | Clearly document in the report that the system uses a **hybrid evaluation architecture**: deterministic NLP rubrics enforce strict technical grading rules (Rules A-H) while the Random Forest model provides continuous rubric validation. | **DEF-003** | **Synthetic Target Formulation in ML Regressor** | `ml/create_target_scores.py`<br>(lines 48–68)<br>`ml/rubric_utils.py` | **HIGH** | The continuous target variable ($0–100$) was generated using a fixed mathematical formula ($0.30 \times \text{Coverage} + 0.25 \times \text{Depth} + 0.25 \times \text{Similarity} + 0.20 \times \text{Alignment}$) rather than genuine human interviewer scores. As a result, the model's high $R^2$ ($0.9985$) reflects function approximation of this formula rather than human grading prediction. | Fully disclose in the report and defense viva that the regressor is a **rubric-emulation model** trained to approximate composite institutional rubrics, not a human-supervised grading predictor. |

| **DEF-005** | **Computer Vision Video Decoupling Ambiguity** | `computer_vision/visual_analyzer.py`<br>`frontend/script.js` (lines 974–1020)<br>`computer_vision/face_mesh_detector.py` | **HIGH** | The report suggests real-time video frames are processed on the server by MediaPipe.
